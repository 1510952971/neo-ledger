# Neo Ledger 完整使用手册

适用版本：Neo Ledger 原生统一客户端 `1.2.7`，Web 端版本以 GitHub Release 为准。

本手册面向普通用户和家庭管理员，按“先能用，再配置高级功能”的顺序编写。文中“数据中心”指主界面侧栏中的数据库图标入口。

## 1. 平台与功能范围

| 平台 | 使用方式 | 当前能力 |
| --- | --- | --- |
| macOS | 原生客户端或 Web/NAS | 完整账本、跨设备同步、自动升级入口 |
| Windows / Linux | 原生客户端或 Web/NAS | 完整账本、跨设备同步、自动升级入口 |
| Android 8.0 及以上 | 原生统一客户端 | 完整账本、通知监听、无障碍支付界面识别（需真机验收） |
| iPhone / iPad | 原生客户端或 Web/PWA | 完整账本、快捷指令/分享入口；系统限制下不读取其他 App 通知 |
| Android 平板 / iPad | 原生客户端 | 完整账本、平板响应式布局；平台能力按对应系统边界执行 |
| NAS | Docker Compose | 24 小时账本服务、同步接口、远程访问基础 |

重要限制：iOS 不允许第三方 App 读取微信或支付宝的通知，因此苹果端不能实现与 Android 完全相同的后台通知监听。苹果端使用快捷指令、共享入口或账单导入，数据仍进入同一个 Neo Ledger 账本。原生客户端的正式版本通过 `native-vX.Y.Z` 标签发布；普通 `vX.Y.Z` 只代表 Web 发布。

## 2. 第一次使用

### 2.1 macOS 一键启动

1. 在 Finder 中打开 Neo Ledger 项目文件夹。
2. 双击 `start.command`。
3. 第一次被系统拦截时，右键 `start.command`，选择“打开”，再确认一次。
4. 启动器会检查 Node.js、安装依赖、处理被占用端口并打开浏览器。
5. 默认地址是 `http://localhost:3000`，实际端口变化时以自动打开的地址为准。

不要关闭启动终端窗口。关闭后，本机账本服务和手机局域网入口也会停止。

### 2.2 Windows / Linux 启动

需要 Node.js 22.13 或更高版本、Git 和 SQLite。进入项目目录后运行：

```bash
npm install
npm run dev
```

浏览器打开 `http://localhost:3000`。需要让手机访问时，系统防火墙必须允许 Node.js 接收局域网连接。

### 2.3 注册第一个账号

1. 打开登录页，选择注册。
2. 设置账户名和密码。
3. 建议同时填写常用邮箱，以便以后找回密码。
4. 邮箱发信服务已配置时，输入收到的 6 位验证码完成注册。
5. 登录后，侧栏显示当前登录名和头像。

账户名和邮箱都可以用于登录。头像、显示名、邮箱和密码可在账号面板中修改。

### 2.4 邮箱收不到验证码

先确认服务端已设置：

```dotenv
RESEND_API_KEY=re_xxxxxxxx
MAIL_FROM=Neo Ledger <noreply@你的域名>
```

验证码 10 分钟有效，输错 5 次作废；同一邮箱 60 秒内不能重复发送，每小时最多 5 封。检查垃圾邮件、Resend 域名验证状态和服务日志。使用 `onboarding@resend.dev` 测试时，只能发到注册 Resend 的那个邮箱。

## 3. 日常记账

### 3.1 新建账本和账户

建议先按用途建立账本，例如“个人”“家庭”“工作室”，再建立真实账户：

- 资产账户：现金、微信余额、支付宝余额、银行卡、投资账户。
- 负债账户：信用卡、消费贷等。
- 账户币种：创建后应与实际流水币种一致。

期初余额应填写开始使用 Neo Ledger 当天的真实余额。之后每笔收支、转账和还款都会联动更新账户余额。

### 3.2 新增收入或支出

1. 点击侧栏快捷记账按钮。
2. 选择“支出”或“收入”。
3. 填写金额、名称、账户、分类和时间。
4. 支出可选择消费情绪；收入可选择收入分类。
5. 保存后检查账户余额是否与预期一致。

金额在数据库中按“分”保存，避免小数累计误差。跨币种记录会保存原币种金额和当时使用的换算信息。

### 3.3 转账与信用卡还款

账户之间移动资金应使用“账户转账”，不要分别新增一笔收入和一笔支出。转入负债账户时，系统会同时减少付款资产并冲减负债。

### 3.4 修改和删除账单

修改金额、类型或账户时，系统会先撤销旧流水对余额的影响，再应用新流水。删除账单时会恢复关联账户余额。操作完成后建议核对相关账户。

### 3.5 预算、订阅和分期

- 预算：设置总预算和分类预算，用于查看当前周期使用情况。
- 订阅：记录周期扣款、付款账户和下次扣款日。
- 分期：记录总金额、期数和还款进度。
- 储蓄目标：从资产账户转入目标时，系统保留整体净资产不变。
- 数码资产：支持自动折旧或手动估值。

## 4. 全平台账单导入

数据中心支持 Excel、WPS、CSV、PDF、图片、HTML 和 TXT，可一次拖入多个文件或多张截图。

原生统一客户端的“全平台账单导入”提供 JSON/CSV 文件选择或粘贴入口；Excel、WPS、PDF、图片、HTML 等扩展识别仍使用 Web 数据中心完成，导入后的流水进入同一账本。

推荐流程：

1. 先在微信、支付宝、银行或电商平台导出官方账单。
2. 打开“数据中心 → 全平台账单导入”。
3. 拖入文件或点击选择文件。
4. 检查来源、识别数量、过滤数量和可能重复项。
5. 为没有匹配成功的支付方式选择现有账户，或按建议新建账户。
6. 删除不需要的预览记录。
7. 点击“确认并批量入库”。

系统会过滤还款、提现等中性资金流，并按导入标识、时间和金额辅助排重。任何自动识别都有误差，正式入库前必须检查预览。

## 5. 备份、恢复和隐私锁

### 5.1 CSV 导出

“导出为 Excel (CSV)”适合查看和统计历史收支。CSV 不是完整备份，不能用于恢复整个账本。

### 5.2 JSON 全量备份

“备份全量数据 (JSON)”包含当前账号拥有的账本、账户、账单、预算、分类、订阅、分期、目标和同步信息。建议：

- 每周保存一次 JSON。
- 大批量导入前保存一次。
- 恢复、升级和修改同步方案前保存一次。
- 备份文件放在加密磁盘或可信云盘中。

### 5.3 恢复 JSON

恢复会覆盖当前账号的全部账本数据，无法撤销：

1. 先导出当前 JSON 作为回退备份。
2. 点击“恢复 JSON 备份”。
3. 选择 Neo Ledger 生成的 JSON 文件。
4. 阅读覆盖提示并确认。
5. 恢复后核对账本数量、账户余额和最近流水。

### 5.4 启动安全锁

在数据中心开启安全锁并设置 4 位 PIN。PIN 适合防止临时查看，不能替代系统账号密码、磁盘加密和 HTTPS。

## 6. Android 微信/支付宝自动记账

### 6.1 工作原理

Android 伴侣使用系统“通知使用权”读取已选择来源的通知。只有同时包含金额和支付关键词的通知才会进入队列。伴侣把通知正文发送到 Neo Ledger 的 `/api/v1/transactions`，服务端解析金额、收支方向、商户和分类。

支持包名：

- 微信：`com.tencent.mm`
- 支付宝：`com.eg.android.AlipayGphone`
- 抖音：`com.ss.android.ugc.aweme`；抖音极速版：`com.ss.android.ugc.aweme.lite`
- 小红书：`com.xingin.xhs`
- 闲鱼：`com.taobao.idlefish`
- 双开版、银行 App 或其他支付 App：可在“其他应用包名”中追加，多个包名用逗号分隔。

### 6.2 安装

测试 APK 可从项目输出目录或 GitHub Actions 构建产物取得。手机提示时，允许当前文件管理器或浏览器“安装未知应用”。正式公开分发前应使用固定的发布证书签名；不同签名的测试 APK 不能直接互相覆盖升级。

最低系统版本为 Android 8.0。安装包不包含第三方运行时库。

### 6.3 一键配置

现在推荐使用一体化快速流程：

1. 手机和 Neo Ledger 服务连接同一个 Wi-Fi；首次使用先在电脑 `.env.local` 开启 `NEO_ENABLE_LAN=true`，并重启服务。
2. 在 Neo Ledger 打开“数据中心 → 自动记账连接”，点击“生成并复制安卓配置”。页面会自动生成密钥并把地址、密钥和账本 ID 组合到剪贴板。
3. 打开 Android 伴侣，点击“一键粘贴配置并开启通知权限”；确认系统权限后即可回到伴侣。
4. 点击“发送 ¥0.01 测试账单”，看到成功后再进行真实通知测试。

伴侣会在粘贴成功后清除剪贴板中的密钥。页面中的“高级设置与其他连接”只用于手动配置、快捷指令、Bark、NAS 或脚本，不是 Android 首次连接的必经步骤。

若快速按钮提示地址是 localhost，请先在数据中心附近设备卡片中重新检测局域网地址，并确认配置使用 `http://192.168.x.x:3000` 这类地址。手机里的 `localhost` 代表手机自身，不能填写 `http://localhost:3000`。

手动配置时需要填写 Neo Ledger 地址、完整自动记账密钥和账本 ID。局域网地址示例：`http://192.168.1.95:3000`。手机里的 `localhost` 代表手机自身，不能填写 `http://localhost:3000`。

### 6.4 权限和后台运行

快速流程会自动打开通知读取权限页面；如果系统没有自动授予，再在伴侣首页点击“开启通知读取权限”。随后只需按手机品牌需要开启自启动和“不限制电量”。最后确认微信和支付宝允许显示交易通知及通知详情。

伴侣会尝试打开小米/Redmi、华为/荣耀、OPPO/一加/realme、vivo/iQOO、魅族的专用自启动页面；找不到时回到系统应用详情页。

### 6.5 测试

1. 点击“发送 ¥0.01 测试账单”。
2. 看到“已入账”后，在 Neo Ledger 刷新账单。
3. 做一笔真实的小额支付。
4. 查看伴侣的“最近捕获”“待发送”和“发送状态”。

真实支付没有被捕获时，先展开微信或支付宝的系统通知，确认通知正文中确实出现了金额。支付 App 隐藏金额时，伴侣无法从系统取得被隐藏的内容。

### 6.6 离线、重试和去重

- 通知先写入手机本地 SQLite 队列，再尝试发送。
- 断网、电脑重启或 NAS 暂时不可用时会自动退避重试。
- 系统重启和伴侣升级后，未发送队列会继续处理。
- 同一通知的 HTTP 重试使用固定幂等 ID，不会重复入账。
- 同一支付通知在 20 秒内更新内容时，会按“通知标识 + 金额”去重。
- 无效密钥等不可重试错误会显示在发送状态中，需要重新配置。

### 6.7 安全说明

自动记账密钥使用 Android Keystore 的 AES-GCM 加密保存在手机中。撤销或重新生成服务端密钥后，旧密钥立即失效。局域网可以使用 HTTP；离开局域网必须使用 HTTPS 域名或可信 VPN，不要把 NAS 的 HTTP 端口直接暴露到公网。

## 7. iPhone / iPad 使用

### 7.1 可以使用的功能

Safari 可以使用完整 Neo Ledger，包括记账、导入、备份、WebDAV 和附近设备同步。可将网页添加到主屏幕，获得接近独立 App 的启动方式。

### 7.2 为什么不能自动监听微信和支付宝

iOS 不向第三方 App 提供读取其他 App 通知的权限。这个限制无法通过普通 App、浏览器或后台进程绕过。任何声称无需越狱即可读取全部微信/支付宝通知的方案都不应接入账本密钥。

### 7.3 iOS 原生快捷指令预填记账

原生 iOS/iPadOS 客户端支持 `neoledger://entry` URL。它只把快捷指令传入的金额、名称、分类和时间预填到“记一笔”表单，不会自动付款，也不会绕过确认直接写入账本。

1. 安装 iOS/iPadOS 原生客户端并登录同一账本。
2. 在“快捷指令”中添加“URL”或“文本”动作，填写类似下面的地址：

```text
neoledger://entry?amount=7.90&type=支出&title=午餐&category=餐饮&source=抖音支付&occurredAt=2026-09-01T12%3A30%3A00%2B08%3A00
```

3. 添加“打开 URL”动作运行它。
4. Neo Ledger 打开“记一笔”底部表单，核对金额、分类和时间后点击“保存”。

金额和时间必须来自快捷指令或用户确认的数据；打开历史订单、照片或普通页面不会触发记账。该入口需要 iOS 真机安装包进行回归，不能用模拟器 ZIP 代替。

### 7.4 HTTP 快捷指令记账

1. 在 Neo Ledger 的“自动记账连接”生成密钥。
2. 点击“复制快捷指令配置”，保留其中的 URL、请求头和 JSON 字段。
3. 打开 iPhone“快捷指令”，新建快捷指令。
4. 添加“询问输入”，分别取得金额和商户。
5. 添加“获取 URL 内容”，方法选择 `POST`。
6. 请求头添加 `Authorization: Bearer 完整密钥` 和 `Content-Type: application/json`。
7. JSON 正文填写 `ledgerId`、`amount`、`merchant`、`source`、`time` 和唯一 `externalId`。
8. 运行一次，确认 Neo Ledger 出现账单后，再把快捷指令放到桌面、锁屏组件或操作按钮。

快捷指令密钥不要出现在公开截图、共享快捷指令或聊天记录中。泄露后立即在 Neo Ledger 撤销并重新生成。

## 8. 附近设备同步

附近设备同步适合手机、平板和电脑在同一局域网内临时传输完整加密账本。

### 8.1 发送设备

1. 两台设备登录同一个 Neo Ledger 账号。
2. 打开“数据中心 → 附近设备同步”。
3. 确认两台设备使用同一个房间码。
4. 点击“生成同步包”。
5. 记录 8 位配对码。
6. 点击“通过局域网发送”。

### 8.2 接收设备

1. 打开同一个局域网地址和数据中心。
2. 等待“局域网待接收同步包”出现。
3. 输入发送设备显示的 8 位配对码。
4. 点击“获取并合并”。
5. 合并后检查最近账单和账户余额。

密文包只在服务端临时保留 15 分钟，成功接收后自动清理。合并按记录更新时间和删除标记处理，不会简单覆盖较新的记录。

### 8.3 在线设备不一致

检查以下项目：

- 是否登录同一个账号。
- 是否使用同一个房间码。
- 是否打开了同一个服务地址和端口。
- 两台设备时间是否正确。
- 防火墙是否允许局域网访问。
- 路由器是否开启了访客网络隔离或 AP 隔离。

在线设备列表只用于确认连接状态，真正的数据传输仍需“生成同步包 → 通过局域网发送 → 获取并合并”。

## 9. WebDAV / 坚果云多端同步

### 9.1 坚果云配置

1. 登录坚果云网页版。
2. 在安全选项中添加第三方应用，生成应用密码。
3. 打开 Neo Ledger 的“多端云同步控制塔”。
4. 点击“使用坚果云”，地址会填为 `https://dav.jianguoyun.com/dav/NeoLedger`。
5. 用户名填写坚果云账号邮箱。
6. 应用密码填写刚生成的第三方应用密码，不是网页登录密码。
7. 设置至少 8 位本地同步密钥。
8. 点击“立即安全同步”。

首次同步会自动创建文件夹和云端文件：

```text
https://dav.jianguoyun.com/dav/NeoLedger/neo-ledger.e2ee.json
```

每台设备必须填写完全相同的本地同步密钥。密钥遗失后，云端密文无法恢复。

### 9.2 三种同步模式

- 立即安全同步：下载云端数据，与本机按记录合并，再上传合并结果。日常使用选这个。
- 仅上传：用当前本机快照替换云端密文。确定本机是正确版本时使用。
- 仅下载并覆盖本机：用云端快照覆盖当前本机。操作前必须先导出 JSON。

### 9.3 密钥保存位置

WebDAV 文件夹地址、用户名和自动同步间隔保存在当前浏览器本地。WebDAV 应用密码和本地同步密钥只保存在当前标签页的 `sessionStorage`，关闭标签页后清除，需要重新填写。

### 9.4 自动同步

可选择每 1、5、15 或 30 分钟检查。页面重新获得焦点或网络恢复时，也会检查是否到了同步时间。浏览器页面完全关闭后不会在系统后台继续执行。

## 10. NAS / Docker 部署

### 10.1 适用场景

NAS 适合让 Neo Ledger 24 小时在线，供电脑、手机、Android 自动记账和快捷指令共同连接。当前仓库提供 `Dockerfile`、`docker-compose.yml` 和持久化 D1 数据卷。

### 10.2 启动

在 NAS 项目目录运行：

```bash
docker compose up -d --build
```

然后打开：

```text
http://NAS局域网IP:3000
```

容器健康检查地址：

```text
http://NAS局域网IP:3000/api/app-update/health
```

正常响应包含 `"ok": true` 和当前版本号。

### 10.3 环境变量

在项目目录创建 `.env`，按需填写：

```dotenv
TZ=Asia/Shanghai
LAN_ORIGIN=http://192.168.1.20:3000
RESEND_API_KEY=
MAIL_FROM=Neo Ledger <noreply@eyeme.online>
AUTH_PUBLIC_ORIGIN=https://ledger.eyeme.online
OLLAMA_URL=http://NAS中的Ollama地址:11434
OLLAMA_MODEL=llama3.1:8b
# 可选安全开关：true 时禁止任何 Ollama 外发，即使 OLLAMA_URL 仍然存在
NEO_AI_EXTERNAL_DISABLED=false
P2P_STUN_URLS=
```

NeoAI 默认只使用当前账本的聚合摘要，不把原始流水直接发送到外部模型。只有在对话面板明确勾选本次会话同意、且 `NEO_AI_EXTERNAL_DISABLED` 未开启时，才会调用 `OLLAMA_URL`；账本切换会清空对话并取消旧请求。模型调用有 15 秒超时和响应大小上限，仍建议在隐私政策中明确 Ollama 的部署位置、日志策略和数据留存责任。

多账号自动记账应在页面生成账号专用密钥。`SYNC_TOKEN` 只用于旧版单用户兼容，不建议多人共用。

### 10.4 数据保存位置

Compose 使用名为 `neo-ledger-data` 的持久化卷，挂载到容器内 `/app/.wrangler`。停止、重建或升级容器不会自动删除这个卷。

不要在 NAS 管理界面选择“同时删除数据卷”，除非已经导出 JSON 并确定不再需要原数据。

### 10.5 更新

更新前先在数据中心导出全量 JSON，然后运行：

```bash
git pull
docker compose up -d --build
```

查看状态和日志：

```bash
docker compose ps
docker compose logs --tail=200 neo-ledger
```

### 10.6 HTTPS 和外网访问

推荐为 NAS 配置独立子域名，例如 `ledger.eyeme.online`，通过 NAS 反向代理转发到容器 `3000` 端口，并申请有效 HTTPS 证书。

安全要求：

- 公网只开放 HTTPS，不直接开放 `3000` 的 HTTP。
- 管理员账号使用独立强密码并绑定可用邮箱。
- 自动记账密钥只保存在可信设备。
- 定期导出 JSON 并备份 Docker 数据卷。
- 不需要公网时优先使用 Tailscale、WireGuard 等可信 VPN。

## 11. 自动记账 HTTP 接口

请求地址：

```text
POST /api/v1/transactions
Authorization: Bearer <账号专用密钥>
Content-Type: application/json
```

结构化支出示例：

```json
{
  "ledgerId": 1,
  "amount": 35.5,
  "merchant": "星巴克",
  "category": "咖啡",
  "source": "shortcut",
  "externalId": "phone-20260729-001",
  "time": "2026-07-29T20:30:00+08:00"
}
```

通知文本示例：

```json
{
  "ledgerId": 1,
  "text": "微信支付 向 星巴克 付款 ¥35.50",
  "source": "notification-forwarder",
  "externalId": "notification-unique-id"
}
```

收入示例：

```json
{
  "ledgerId": 1,
  "amount": 200,
  "merchant": "工资",
  "type": "收入",
  "incomeCategory": "工资收入",
  "externalId": "salary-202607"
}
```

`externalId` 或 `Idempotency-Key` 必须对同一事件保持不变。同一 ID 用于不同内容会返回 `409`。未指定账户时，系统使用该账本的第一个资产账户。账号专用接口每分钟最多接收 60 次请求。

## 12. 版本更新

本机启动器模式可在数据中心检查 GitHub Release 并一键升级。升级流程会：

1. 检查工作区是否干净。
2. 在线备份 SQLite/D1 数据库。
3. 下载与版本号一致的稳定标签。
4. 安装依赖并构建。
5. 重启并检查版本、接口和数据库迁移。
6. 失败时切回旧版本并恢复数据库。

Docker/NAS 使用第 10.5 节的镜像重建流程，不使用桌面版一键升级。

Android 伴侣升级必须保持相同签名证书。GitHub Actions 的临时测试签名不应当作正式长期发布证书。

## 13. 常见问题

### 手机打开局域网地址显示 Not Found 或无法连接

确认地址包含当前实际端口，例如 `http://192.168.1.95:3000`。在数据中心点击“重新检测地址”，同时检查电脑防火墙、访客 Wi-Fi 隔离和服务终端是否仍在运行。

### 手机密码正确但登录失败

确认手机访问的是与电脑相同的地址和端口，且不是旧端口上的另一个服务。清除该地址的浏览器缓存后重新登录，并检查手机时间是否正确。

### Android 测试成功，真实支付没有入账

打开微信或支付宝通知详情，确认通知正文包含金额和付款/到账关键词；检查通知使用权、自启动、省电限制和伴侣“最近捕获”状态。

### Android 显示 401 或 SYNC_TOKEN 无效

密钥已撤销、重新生成或粘贴不完整。回到数据中心重新生成，复制安卓配置并再次粘贴。重新生成会立即让旧设备失效。

### Android 一直显示待发送

确认 Neo Ledger 地址能在手机浏览器打开。局域网使用时服务必须保持运行；外网地址必须是可信 HTTPS。点击“立即发送待处理账单”查看最新错误。

### 坚果云 WebDAV 返回 401

用户名应为坚果云账号邮箱，密码应为第三方应用密码，不是登录密码。重新生成应用密码后再试。

### WebDAV 提示无法解密

本地同步密钥与创建云端文件时使用的密钥不一致。不要反复尝试覆盖，先找回原密钥或在原设备导出 JSON。

### 附近设备互相看不到

确认账号、房间码、服务地址和端口完全一致。部分路由器会隔离无线设备，可改用 WebDAV 或下载加密同步包。

### 恢复备份后数据不对

立即停止新增账单，使用恢复前保存的 JSON 再次恢复。CSV 不能作为完整恢复文件。
